# Meen Fina (مين فينا؟) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a mobile-first PWA where a friend group posts "who…?" questions, members vote for one member anonymously, and a leaderboard is revealed to everyone at once.

**Architecture:** React (Vite, TypeScript) PWA on Firebase Hosting. All state changes go through Cloud Functions (2nd gen callables) that enforce membership and permissions; individual votes live in a Firestore collection no client can touch, and question documents carry only public state. Pure game rules live in one dependency-free module (`functions/src/shared` + `functions/src/core`) that the web app also imports for types and constants.

**Tech Stack:** Node 22, TypeScript 5, npm workspaces, Firebase (Auth/Google, Firestore, Functions v2, FCM, Hosting), firebase-admin 13, firebase-functions 6, firebase JS SDK 11, React 18, Vite 5, vite-plugin-pwa (injectManifest), react-router-dom 6, i18next + react-i18next, Vitest, @firebase/rules-unit-testing, firebase-tools 14 emulators.

**Spec:** `docs/plans/2026-11-13-friends-vote-design.md`

## Global Constraints

- Firebase region: `europe-west1` for Firestore (default database) and all functions.
- Every function sets `maxInstances: 2` (via `setGlobalOptions`).
- No Cloud Storage. No Firestore listeners outside the current group (home screen uses one `array-contains` query).
- Firestore rules: clients can never read or write `votes/*` or `codes/*`; clients never write `groups/**`.
- Join code: 6 chars from alphabet `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (no 0/O/1/I).
- Limits: max 50 members per group; ≥3 members to post a question; question text 1–150 chars (trimmed); group name 1–40 chars (trimmed) **[my call]**.
- Early reveal: asker or admin, only with ≥3 votes. Auto-reveal: when every eligible voter has voted AND ≥3 votes.
- Fewer than 5 eligible voters at reveal → store and show winners only, no counts.
- 48h after posting: reveal if ≥3 votes, else status `expired`. Checked hourly.
- Fewer than 3 eligible voters left on an open question → `expired` immediately.
- Cannot vote for yourself. Vote changeable until reveal. Late joiners are not eligible.
- Languages `en` and `ar`; Arabic mirrors layout (`<html dir="rtl">`). Question text rendered with `dir="auto"`.
- Never request notification permission on first load; on iOS Safari (not standalone) show the "Add to Home Screen" guide instead.
- Commit format `type: short description`; stage specific files (never `git add -A`); end every commit with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Amendments during execution

- **2026-11-13, Task 6 review (overrides Tasks 2/5/6 text below):** votes cast *for* a removed member are NOT deleted and those voters stay in `votedUids` (deleting them leaked who voted for the leaver via the client-readable `votedUids`). `removeMemberFromQuestion` deletes only the leaver's own vote. "Valid votes" = voter and target both still eligible (`countValidVotes`). Automatic reveals (last vote, member removal) stay open if valid votes < 3; manual "Reveal now" fails `too-few-votes` if valid votes < 3; the 48h job (Task 7) expires if valid votes < 3. `finalizeQuestion` still converts `'reveal'` → `'expire'` as a safety net.
- `removeFromOpenQuestions` is split into `loadOpenQuestionsFor(db, tx, groupId, uid)` (reads) + `applyMemberRemoval(db, tx, loaded, uid, now)` (writes). `getGroupOrFail` takes `(db, tx, groupId)`.

## Review Focus

1. **Member removed while their vote targets/was cast on an open question** — their own vote is deleted; votes *for* them stay as void votes and those voters stay in `votedUids` (see Amendments); auto-reveal/expire is re-evaluated on valid votes. Test in Task 6.
2. **Two people cast the last vote at the same moment** — exactly one reveal happens and `results` is computed from all votes. `castVote` runs in a transaction; test in Task 5 with `Promise.all`.
3. **Kicked user retries the old link or a new code** — `joinGroup` returns `banned` regardless of code; after "Allow back" they can join. Test in Task 6.
4. **Leaked tallies via the question doc in small groups** — for <5 eligible voters the stored `results` has no counts at all. Test in Task 2 (core) and Task 5 (stored doc).
5. **Hourly expiry hitting an already-revealed or deleted question** — expiry only touches `status == 'open'` docs inside a transaction and is a no-op otherwise. Test in Task 7.
